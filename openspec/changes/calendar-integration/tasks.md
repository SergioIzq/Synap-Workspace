# Tasks

Orden: primero el backend, que el frontend necesita (persistencia → lectura → conexión → asistente → briefing); luego el frontend. Cada repo cierra con su build y el frontend con una prueba de punta a punta. La única Open Question del design (el valor final del umbral de similitud) no cambia ninguna tarea. Las variables de `docker-compose.yml` y el runbook de este repo quedan fuera, como dice el design en el Migration Plan, paso 3.
